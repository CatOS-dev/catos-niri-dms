# catos-niri-dms

Complete CatOS Niri desktop Profile powered by Dank Material Shell.

The repository contains the installed Profile tree directly:

```text
usr/share/catdot/profiles/catos-niri-dms/profile.toml
usr/share/catos-niri-dms/...
```

Select the Profile with:

```sh
catdot select catos-niri-dms
```

Catdot installs the exact package names declared by the Profile and maps the
content below `/usr/share/catos-niri-dms` into the user's HOME. Switching a
Profile does not restart applications or the desktop session.

The global Niri helper commands are owned by the separate `catos-niri-utils`
package. This Profile package does not install executables into `/usr/bin`.

## Configuration ownership

The Profile owns and refreshes the stable desktop baseline:

```text
.config/niri/config.kdl
.config/niri/catos/session.kdl
.config/niri/catos/layout.kdl
.config/niri/catos/animations.kdl
.config/niri/catos/windowrules.kdl
.config/niri/catos/recent-windows.kdl
.config/niri/catos/tools.kdl
.config/environment.d/80-catos-niri.conf
.config/xdg-desktop-portal/niri-portals.conf
.gtkrc-2.0
.config/gtk-3.0/settings.ini
.config/gtk-3.0/gtk.css
.config/gtk-4.0/settings.ini
.config/gtk-4.0/gtk.css
.icons/default/index.theme
```

Run the following command to explicitly accept a newer installed revision:

```sh
catdot update catos-niri-dms
```

DMS owns runtime color output such as `dank-colors.css`, Niri color fragments,
Qt color schemes and terminal palettes. Catdot does not manage those generated
files. The GTK baseline uses adw-gtk3 instead of a fixed Graphite palette, and
Qt 6 uses qt6ct-kde with the KColorScheme generated by DMS.

## Seed configuration

All other files under `/usr/share/catos-niri-dms` are initial Profile seeds.
The managed main Niri config includes DMS fragments plus the profile-scoped
`~/.config/niri/custom/catos-niri-dms/` directory. Its `input.kdl`,
`input-overrides.kdl`, `outputs.kdl`, and `rules.kdl` files are seeded once and are never managed, so
later selections and updates preserve user changes.

Niri merges input sections across includes but replaces each pointing-device
section rather than merging its individual properties. To let DMS settings
persist, the legacy `custom/input.kdl` is loaded **before** `dms/input.kdl`.
Keyboard settings in the legacy file continue to apply. Put any intentional
mouse, touchpad or trackpoint overrides in `custom/input-overrides.kdl`, which
is loaded **after** DMS. Existing users who customized pointing devices in
`custom/input.kdl` should move those device blocks to the override file;
user-owned configuration is not modified automatically.

Niri's overview backdrop has two wallpaper modes:

- By default DMS uses the regular, unblurred `quickshell` wallpaper. CatOS
  places it inside the overview backdrop, including between workspaces.
- If enabling DMS **Duplicate Wallpaper with Blur**, add the following rule
  to `~/.config/niri/custom/catos-niri-dms/rules.kdl` to keep the desktop
  sharp while DMS places `dms:blurwallpaper` in the overview backdrop:

```kdl
layer-rule {
    match namespace="^quickshell$"
    place-within-backdrop false
}
```

Remove that override when turning off Duplicate Wallpaper with Blur. DMS
1.6.3 does not generate a conditional rule tied to this setting, so toggling
the option in DMS alone does not switch Niri's backdrop placement.

The following application integrations are also seeds and remain user-owned:

- Ghostty and Satty configuration;
- qt6ct baseline settings;
- Fcitx5, Fuzzel, btop and Cava activation settings;
- Matugen user templates and their generated application color files.

If a user already has one of these files, Catdot preserves it. The templates can
be merged manually from `/usr/share/catos-niri-dms` when desired.

Niri starts Xwayland Satellite and DMS directly from the managed session module.
Terminal and launcher bindings invoke Ghostty and DMS directly; no Catdot
runtime wrapper is used. Native Print bindings remain available, while the
Shift+Print variants open the captured image in Satty.
